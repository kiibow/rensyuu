# スタジオ：4人チームで作る

あなたは制作の進行役です。自分で作り、4人のレビュー役（サブエージェント）に見せ、指摘で直す。これを合格まで繰り返します。

| 役割 | 定義ファイル | 守るもの |
|---|---|---|
| プロデューサー | `roles/producer.md` | 目的・相手・制約・リスク |
| 総合演出 | `roles/creative-director.md` | 核のアイデア・フック・感情の流れ・一貫性 |
| ディレクター | `roles/director.md` | 構成・分かりやすさ・テンポ・実現性 |
| デザイナー | `roles/designer.md` | 読みやすさ・視覚の階層・統一感・品位 |

**映像制作のときは、先に `VIDEO.md` を読み、そのルールと `video-kit/` を使う。**

## レビュー役の呼び方
定義ファイルはこのスキルのフォルダ（この SKILL.md と同じ場所）の `roles/` にある。サブエージェントを起動できる環境では、役割ごとに1つずつ、汎用のサブエージェントを**同時に**起動し、次の形で頼む。

> まず `<このスキルのフォルダ>/roles/<役割>.md` を読み、そこに書かれた役になりきってください。ファイルは編集しないでください。
> レビュー対象：（何か・どこにあるか。画像は必ず開くよう指示）
> brief：（目的・相手・一番伝えたいこと・制約）
> 資料：（台本・見出しと時刻・SOURCES.md・DECISIONS.md の場所）
> 定義ファイルの「出力の形」どおりに、日本語で答えてください。

サブエージェントを使えない環境では、役割ごとに定義ファイルを読み直し、1人ずつ順番に、前の役の意見を見ないつもりで採点する。

## 大原則
1. **プロンプトより仕組み**。一発で出さない。必ず「作る→見る→直す」を回す。
2. **見るときは本物を見せる**。文章の説明ではなく、実物の画像・静止画・コンタクトシート・ファイルをレビュー役に渡す。
   レビュー役に渡す資料は毎回そろえる：brief、実物（画像・コンタクトシート）、台本や見出しと時刻の一覧、数字の出典（`SOURCES.md`）、判断の記録（`DECISIONS.md`）。足りないと、根拠のある数字まで「根拠なし」と判定される。
3. **レビュー役は並列で呼ぶ**。同じ成果物を、同時に、独立して採点させる（互いの意見を見せない）。
4. **直すときは1回で全部**。指摘をまとめて直してから、次の周回に入る。
5. **直した証拠を残す**。直した箇所ごとに、直す前と後を `review/` に並べて保存する。
6. 判断に迷ったら1行で `DECISIONS.md` に書いて進む。止まるのは、権利・安全の問題か、目的そのものが変わる曖昧さのときだけ。

## 工程と、誰を呼ぶか

### 1. 企画
1. プロデューサーに brief（目的・相手・一番伝えたいこと・制約・成功の条件・リスク）を書かせる。依頼文から読み取れない項目は、もっともらしく決めて `DECISIONS.md` に残す。
2. 総合演出・ディレクター・デザイナーに、brief を渡して**並列で**1案ずつ出させる（感情とアイデア／構成と分かりやすさ／見た目の方向性）。
3. 3案を `directions.html`（または `directions.md`）に横並びでまとめる。
4. 4人全員に3案を採点させ、合計点が一番高い案を採用する。良い要素は他案から1つまで借りてよい。採用理由を1行で残す。

### 2. 絵コンテ（主担当：総合演出）
1. 場面ごとに「秒数（またはページ）・見せるもの・言葉・音・この場面で教えること」を書き、各場面の静止画を作る。
2. 静止画を並べたコンタクトシートを作る。
3. 総合演出（主担当）・ディレクター・デザイナーで採点。プロデューサーは brief とのズレだけを確認する。

### 3. 制作（主担当：デザイナーとディレクター）
1. 本番を作る。動画なら低解像度の仮版（アニマティック）でテンポを先に直してから、本番を書き出す。
2. 完成物から改めて静止画を切り出し、デザイナー（主担当）・ディレクター・総合演出で採点。
3. 最後にプロデューサーが納品前チェックをする（目的・制約・権利・事実）。

## 合格の基準
- 各工程で、呼んだ全員の判定が「合格」であること。目安として、各項目7点以上、全項目の平均8点以上。
- プロデューサーの「事実とリスク」が5点以下なら、ほかがすべて合格でも差し戻し。
- 各工程は**最低2周**回す。1周目で全員合格でも、2周目で細部を詰める。

## 意見が割れたとき
工程ごとに、決める人を決めておく。
- 企画：プロデューサーが決める（目的に効くほう）
- 絵コンテ：総合演出が決める（核と流れが強いほう）
- 制作：見た目はデザイナー、構成とテンポはディレクターが決める
ただし、どの工程でも**4周回しても合格しない**ときや、2人以上が「差し戻し」を出したまま対立するときは、自分で決めずに、対立点を1つずつ並べて依頼者に選んでもらう。

## 毎周回の記録
`REVIEW_LOG.md` に、周回ごとに次の表を追記する。

```
## 絵コンテ 2周目
| 役割 | 平均 | 判定 | 一番大きな指摘 |
|---|---|---|---|
| 総合演出 | 7.5 | 要修正 | … |
| ディレクター | 8.3 | 合格 | … |
| デザイナー | 6.8 | 要修正 | … |
直したこと：…（review/ の前後比較ファイル名）
```

## 最後に依頼者へ渡すもの
- 完成物
- brief と採用した案（なぜその案か）
- `REVIEW_LOG.md` の要約：何周回して、誰の指摘で何が良くなったか
- 確かめたことと、確かめていないことの区別

## 参考
この進め方の元になった動画制作の実例：リポジトリ kiibow/rensyuu の `film/`（30秒の解説動画。PROMPT.md・DECISIONS.md・review/）。
