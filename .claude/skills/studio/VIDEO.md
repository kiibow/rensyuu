# 映像制作のルール（studio の映像版）

動画・モーショングラフィックス・解説映像・ショート動画を作るときは、SKILL.md の手順に加えて、このファイルのルールに従う。
道具は `video-kit/`（draw(t) の雛形・書き出し・検証）。

## 0. 一番大事なこと
- **動画はプロンプト一発で出さない。** AIは動画ファイルを直接出さず、「t秒目の1コマを描くプログラム」を書く。描いたコマを自分で見て、直す。
- **自分のコマを見る。** 静止画・コンタクトシートを必ず画像として開いて確かめる。見ていないものを「できた」と言わない。

## 1. 企画（主担当：プロデューサー）
プロデューサーの brief に、映像では次を必ず入れる。
- 一文のアイデア（見終わった人が言えるようになる一文）
- 相手が今信じていること（＝覆す思い込み）
- 尺（30〜90秒）と形式（16:9 を基本に、9:16・1:1 は組み替え）
- ナレーションの有無（ないなら、画面の見出しが字幕を兼ねる）
- 使える素材（ブランド・実物の画面・データ）。ない場合は、その旨を `DECISIONS.md` に書く

3人（演出・ディレクター・デザイナー）が1案ずつ出し、`directions.html` に並べて4人で採点する。

## 2. 構成の型（尺に対する割合）
| 区間 | 割合 | 中身 |
|---|---|---|
| 問い | 0〜10% | 相手が間違えている「もの」を**絵で**見せる。文字だけの冒頭にしない |
| 仕組み | 10〜35% | 一番小さい正しい図を、1拍に1要素ずつ組み立てる。専門用語やコードは画面に出さない |
| 実例 | 35〜75% | 本物の例で、原因と結果を画面上で起こす。主張は**実物の比較**で証明する |
| 転換 | 75〜90% | 1つだけ変えて、結果が変わるのを見せる。**全体で一番の見せ場**。読む時間を十分に取る |
| まとめ | 90〜100% | 最初の絵をもう一度、今度は正しく読めるように。最後に、相手が明日できる具体的な一手 |

## 3. 絵コンテ（主担当：総合演出）
- 場面ごとに：秒数／教えること（1つ）／画面（重要な順）／動き（入り・見せ場・止まる・出る）／言葉（1行8語・2行まで）／音（見せ場の合図）／この場面のあとで相手が言えること
- 各場面の静止画を作り、コンタクトシートにして3人で採点する
- 「直した後」の絵は「直す前」より**明らかに魅力的**に描く（地味な線画にしない）

## 4. アニマティック → 本番（主担当：ディレクター → デザイナー）
1. 低解像度でテンポを確かめる。`node render.mjs timing` で、全部の行に読む時間があるか機械的に確かめる（日本語は1秒に約8文字、「文字数÷8＋0.5秒」以上）
2. ディレクターが秒単位で採点し、テンポを直す
3. 本番を書き出し、完成映像から1拍ごとに切り出したコンタクトシートで、デザイナーが主担当で採点する
4. 最後にプロデューサーが納品前チェック（主張の証明・出典・権利・次の一手）

## 5. 見た目の基準（デザイナーが数値で確かめる）
- 背景は温かいニュートラル、アクセント1色、書体2つ、グリッド1つ
- 文字の最小サイズ：16:9 で見出し64px・ラベル40px、9:16 でラベル44px（390px幅で16px相当）
- コントラスト4.5:1以上。色だけで情報を伝えない（形・文字も使う）
- 禁止：ネオンの光、3Dの塊、グラデーションのタイトルカード、漂う粒子、根拠のない数字（「悪い例」として枠の中で見せる場合を除く）
- 図は画面を大きく使う（幅75%・高さ60%程度）。一番大事な2か所（転換と結論）は他より目立たせる
- 動きは意味のあるときだけ。跳ねずに止まる（臨界減衰ばね）。読ませている間はカメラを動かさない

## 6. 音
- テンポの決まった伴奏（Web Audio）と、核のアイデアで鳴る短いモチーフ1つ
- 効果音は意味のある動作にだけ
- 約 -16 LUFS、true peak -1.5 dBTP 以下（`build.sh` が自動で合わせる）

## 7. 書き出しと検証（`video-kit/build.sh` → `check.sh`）
- 書き出すもの：`master_16x9.mp4`・`cut_9x16.mp4`・`cut_1x1.mp4`・`master_16x9_reduced_motion.mp4`・`captions.srt`・`contact.png`
- `check.sh` が確かめること：同じコマを2回描いて完全一致／解像度と長さ／音量／コンタクトシート／縦型を390px幅に縮めた画像
- `contact.png` と `check_390.png` は**必ず自分で開いて見る**
- README には、実際に確かめたことだけを書く。確かめていないこと（耳で聞いていない、など）も明記する

## 8. video-kit の使い方
```sh
cp -r <このスキルのフォルダ>/video-kit ./film   # 作品ごとにコピー
cd film && fonts/get-fonts.sh                    # フォント（Noto Sans JP / JetBrains Mono、OFL）
# src/film.js の TOKENS・TIMELINE・drawStage を書き換える
node render.mjs timing                           # 読む時間のチェック
node render.mjs beats 960 540 stills             # 1拍ごとの静止画（絵コンテ・レビュー用）
./build.sh                                       # 全形式の書き出し＋検証
```
必要なもの：Node 22、Playwright（Chromium）、ffmpeg。

## 9. 過去の学び（4人レビューで実際に出た指摘）
- 正しいけど核と関係ない「仕組みの裏側」の場面は、一般向けでは別の話になる → 削る
- 「AよりBが効く」と言うなら、AとBを実物で並べる。作った図だけで言い切らない
- 一番大事な転換が一番短かった（1秒しか読めない）→ 転換に時間を回す
- 同じ見出しで似た周回を3回は、だれる → 2回にする
- 「直した後」が線画で地味だと、派手な「直す前」のほうが良く見えてしまう
- レビュー役に出典を渡し忘れると、根拠のある数字も「根拠なし」と判定される → 資料は毎回そろえる
